Migrations run unattended when a PR merges, with nobody watching. Report as HIGH a migration with no down migration (or an up that its down does not undo), and a change that takes a long lock on a table that may be large: adding a column with a volatile default, changing a column's type, adding a NOT NULL without a backfill, or creating an index without CONCURRENTLY. Report as HIGH a migration that fails on a table that already has data (a new unique or foreign-key constraint over existing rows, a NOT NULL over rows that hold NULL), even if it passes on an empty one. Advice that assumes Supabase or row-level security applies only if this repo uses them; otherwise skip it.
